# Simulation-based acceptance and issue traceability

[Scope](scope.json) records the owner decision: all required hardware is simulated and template/generic assets may be used in every case. [Issue index](issues.json) links the umbrella and 24 workstreams, their dependencies, detailed scope and case ownership. [Coverage requirements](coverage-requirements.json) track obligations for every associated standard and all 43 cases; they do not claim class extraction, template delivery or simulator implementation is finished.

[cases.json](cases.json) contains 43 proposed cases, all NOT_RUN with null result receipts; [workplan.json](workplan.json) contains ten ordered phases. Actual software execution, independent simulation oracles and authentic native/admission results remain required. Physical procurement, customer site data, CHIL/PHIL laboratories and physical commissioning are not corpus-admission gates.

[The complete workplan](../WORKPLAN.md) retains official tooling, prerequisites, runtime-reset authorization and first-admission versus deployment sequencing. [Verification summary](../verification-summary.json) is package consistency only.
