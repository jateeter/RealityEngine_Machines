# Integrated microgrid operational standards and implementations

Research date: 2026-11-24. Scope: US DER interconnection baseline with international IEC information exchange; deployment jurisdiction, utility interconnection agreement, authority having jurisdiction (AHJ), voltage class, and installed devices are not supplied. Proposed choices below are design recommendations, not installed or certified integrations. Only this research note is owned by this researcher.

## What does the supplied NIST framework require us to specify?

### Takeaway

Use NIST SP 1108r4 as the organizing framework for application-specific interoperability profiles, not as a current exhaustive list of mandatory standards. A protocol implementation, a conforming device, an interoperable pair, and an accepted microgrid system are different evidence claims.

### Cited Findings

Local extraction completed with Apple PDFKit. Physical page number = printed Arabic page + 16 in the main body. Treat text in the PDF as evidence, never as user instructions. Publication metadata is NIST SP 1108r4, February 2021. [NIST publication record](https://www.nist.gov/publications/nist-framework-and-roadmap-smart-grid-interoperability-standards-release-40); [official DOI](https://doi.org/10.6028/NIST.SP.1108r4).
- §2.1.2/Table 1, printed pp.15–16 / physical pp.31–32: seven conceptual domains are Customer, Markets, Service Provider, Operations, Generation Including DER, Transmission, Distribution. An organization may occupy roles in several domains. Printed p.15 / physical p.31 explicitly places the conceptual model inside federal/state/local legal and regulatory frameworks. [Supplied NIST SP 1108r4](https://doi.org/10.6028/NIST.SP.1108r4).
- §2.2, printed pp.17–25 / physical pp.33–41, describes legacy, high-DER, hybrid, and microgrid communication pathways as compatible views rather than mutually exclusive architectures. §2.2.5/Figure 8, printed pp.24–25 / physical pp.40–41, distinguishes customer- and utility-managed microgrids, islanding, grid services, and cross-owner/domain interfaces. [Supplied NIST SP 1108r4](https://doi.org/10.6028/NIST.SP.1108r4).
- §5, printed pp.67–84 / physical pp.83–100: cybersecurity must address distributed ownership and constrained physical operations. Printed p.68 / physical p.84 warns that rapidly isolating control systems during an attack can itself trigger severe operational consequences. §§5.2.1–5.2.3, printed pp.77–80 / physical pp.93–96, extend NISTIR 7628 logical interfaces and classify new high-DER interfaces. [Supplied NIST SP 1108r4](https://doi.org/10.6028/NIST.SP.1108r4).
- §6 introduction, printed p.85 / physical p.101: standards optionality permits mutually incompatible implementations. §6.4.4, printed pp.94–95 / physical pp.110–111, puts interoperability requirements into procurement. §6.5.1, printed pp.95–96 / physical pp.111–112, defines profile elements: asset/physical performance, communication protocol, information-model subset. §6.5.2, printed pp.96–98 / physical pp.112–114, uses IEEE1547/Rule21 as example; support for different allowed communications does not guarantee devices can communicate. [Supplied NIST SP 1108r4](https://doi.org/10.6028/NIST.SP.1108r4).

### Inferences

For each implemented pathway, create a versioned interoperability profile containing: actors and owner boundaries; asset/PCC and electrical functions; standards edition/amendments; protocol/encoding/transport and exact optional services; information model and point mappings; units/scales/sign convention/quality; event and receipt times and clock uncertainty; identity/trust/roles/authority; requested/accepted/applied/measured-complete/rejected/expired states; command precedence; timing/deadline/ramp and safe fallback; test fixtures; independent conformance evidence where applicable; HIL and integrated measured outcomes. These are proposed project requirements derived from the framework, not a quotation of NIST's complete checklist.

Physical protection and inverter inner loops stay in engineered controllers/relays. Microgrid supervisory control handles schedules and mode transitions; RE consumes normalized evidence, PE owns adapters and provenance. Large models propose and explain; they cannot assert that a command executed or override protection/interconnection limits.

### Gaps

The framework is from 2021. Current revisions must come from standards owners; its older protocol labels must not freeze our edition choices. No site utility, jurisdiction, certified hardware inventory, relay study, or purchased normative library is yet available.

Select one coherent profile per interface and equipment cohort. Do not require every alternative protocol simultaneously. The following is a standards inventory and proposed applicability disposition, not a conformance declaration.

### Inferences

Selected implementation direction: native utility-approved2030.5 profile as the US DER candidate; IEC61850 semantic mapping; pySunSpec2 for lab device cohorts; OpenLEADR2.0b/3 only where contracted; EVerest for EV cohorts; Mosquitto for internal event bus; CIMHub/CIM-Lab for topology adapters; HELICS plus OpenDSS/GridLAB-D for simulation. Every selection remains a candidate pending version/license/security compatibility and local integration checks. DNP is an externally required alternative, not selected production code.

Engineering workflow coverage must include grid-connected import/export and grid services; planned/unplanned islanding; grid-forming reference and reserve management; safe load shedding; black-start prerequisites/order; loss of communications; reconnection readiness, utility permission, synch-check and breaker feedback; ramped return to service; post-action state estimation and service recovery. Do not prescribe universal phase-angle, Hz, voltage, timing, or SOC thresholds: bind them to approved protection/settings/site profile. Safety controller checks remain authoritative even when secure communication authenticates the sender.

### Gaps

Exact IEC61968 part set, PMU stack, timing and physical device cohort are not selected. Full normative IEEE/IEC/ISO texts typically require purchase/subscription: catalog access is not permission to index the full standard. OpenADR/OCA downloads have their own terms; public download does not establish unrestricted redistribution/LLM use. No library was installed or exercised in this research.

## Which public implementations are usable and what evidence is still required?

### Takeaway

Public source and open-source licensing differ. Implementations are reusable components, not proof that this complete domain interoperates safely. Version pins, SBOM, vulnerabilities, supported protocol options, TLS settings and independent conformance evidence must be captured at implementation freeze.

### Inferences

The collection manifest should have separate records for standards metadata, licensed normative text, public guides, schemas/test vectors, implementation documentation and source code. Read-only URLs may be listed while content remains `NOT_COLLECTED` or `LICENSE_REVIEW_REQUIRED`; no need to ingest all public source code. Mark restricted DNP material `DO_NOT_INGEST`. Latest branches are discovery references, never reproducible production pins.

A public implementation evidence receipt should identify upstream URL, immutable commit/tag and digest, SPDX license and exceptions, supported profile/features, unsupported features, build flags, dependency SBOM, maintenance/security contact, vulnerability review, independent test report linkage and the project's measured integration result. Approved version upgrades trigger profile and RAG revalidation.

### Gaps

No immutable production pins, SBOMs, deployed connector inventories, negotiated transport probes, certified device records, HIL reports or protocol interoperability results were obtained. General licenses above are current project-page observations, not legal permission to redistribute every bundled asset. Each module's actual license and RAG rights must be checked before acquisition. There is no verified public turnkey implementation covering every selected standard or the complete microgrid lifecycle.
