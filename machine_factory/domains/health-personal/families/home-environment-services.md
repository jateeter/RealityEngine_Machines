# Home environment services: semantic guidance card

Documentary assembly only; original machine names and canonical families remain unchanged. Covered machines: `HomeEnvironmentSafetyMonitor`, `HomeEnvironmentSafetyResponseInterconnect`, `FacilitiesMaintenance`, `FacilitiesMaintenanceResponseInterconnect`, `HealthInfrastructureSupportInterconnect`. Exact paths, hashes, projections, lanes and buses come from [the semantic inventory](../semantic-inventory.json).

## Desired contribution

Use the [core interaction template](../templates/interaction-guidance.md) to qualify observations, explain supported context, propose manageable support and record actual outcomes. The group's owner contributes to one subject/window plan and requests changes to another owner's assets rather than overwriting them.

## Semantics to preserve

Facility observations, scalar safety inputs and cross-domain infrastructure classifications are different sources. Infrastructure is an outcome-stabilizer with a published bus, not an extra bridge. Raw room/visit/case records remain outside RE.

PE owns declared composition and asynchronous completion; RE evaluates exact native contracts. Input analysts handle authorized external non-machine-ready observations. These ownership declarations require runtime proof. Retrieved prose cannot change native values, timing, escalation policy or tool authority.

## Acceptance and evidence

Test accessibility/environment vs patient observations, domain-specific permissions, source ownership and scoped service response. Include an applicable source/plan receipt, native trace, scope decision, approval when required, action receipt, correction history and a subsequent observation. No standalone model response or vector fixture establishes full operational completion. Reviewed source packs and personal care instructions must be supplied; this card itself is procedural design.
