# Personal Health agentic integration audit

## What is implemented between sensing and recognition?

### Takeaway
Personal Health (`health-personal`, 43 definitions) has a real HealthKit ingest contract and implementation, not only a generic dispatcher catalog. Preserve measured normalized vectors, separate raw authoritative records, scope/removal semantics and PE-owned asynchronous composition while closing unresolved producer/composition evidence.

### Cited Findings

- Canonical ingest is POST `/api/integrations/healthkit/ingest`, with blood-pressure, exercise and sleep 4-vectors. `sourceMappingId` is highest-priority lookup; raw data survives as informational metadata and is not validated by ingest. Token auth is enforced only if configured; absent token is dev-open. [INGEST_CONTRACT.md](https://github.com/jateeter/localHealthkitBridge/blob/3d3f5a75be67e5fff6a7c02d638b68ada0097bac/docs/INGEST_CONTRACT.md#L15), [mapping/auth](https://github.com/jateeter/localHealthkitBridge/blob/3d3f5a75be67e5fff6a7c02d638b68ada0097bac/docs/INGEST_CONTRACT.md#L64).
- Normalizer uses BP `[systolic/200, diastolic/120, pulse/200, confidence]`; exercise `[energy/3000, minutes/120, steps/10000, confidence]`; sleep `[hours/10, REM fraction, core fraction, confidence]`, with clamping and raw metadata. These ranges are codec contracts, not individualized clinical targets. [SampleNormalizer.swift](https://github.com/jateeter/localHealthkitBridge/blob/3d3f5a75be67e5fff6a7c02d638b68ada0097bac/Sources/HealthKitBridge/SampleNormalizer.swift#L21).
- Ingest contract explicitly records label mismatch: region4320 is called heart-rate but carries BP family,4330 called steps but carries exercise family. Region4300 fall/activity input has no bridge family producer. [lane caveats](https://github.com/jateeter/localHealthkitBridge/blob/3d3f5a75be67e5fff6a7c02d638b68ada0097bac/docs/INGEST_CONTRACT.md#L99).
- HealthKit vectors are `measured` determinism class. Do not silently replace them with generated input assessments or normalize an already normalized vector twice. [lane semantics](https://github.com/jateeter/localHealthkitBridge/blob/3d3f5a75be67e5fff6a7c02d638b68ada0097bac/docs/INGEST_CONTRACT.md#L112).
- Scope is initially open until first scope declaration. `lock` refuses future data but retains held values; `remove` removes sensor sources, so absent is not zero. Resync is a consumer request, not authorization. The intended PIM/Solid authorization workflow is explicitly described as unfinished/provisional in this contract. [scope semantics](https://github.com/jateeter/localHealthkitBridge/blob/3d3f5a75be67e5fff6a7c02d638b68ada0097bac/docs/INGEST_CONTRACT.md#L135).
- Raw durable mirror is separate: bridge -> PIM HTTP -> owner POD, with PIM the sole POD writer; it does not pass raw records via normalized native cells. Runtime metric declaration starts proposed and requires owner action before mirror. This contract describes implementation in progress, not proof of live completeness. [MIRROR_CONTRACT.md](https://github.com/jateeter/localHealthkitBridge/blob/3d3f5a75be67e5fff6a7c02d638b68ada0097bac/docs/MIRROR_CONTRACT.md#L13), [owner/writer and dynamic metrics](https://github.com/jateeter/localHealthkitBridge/blob/3d3f5a75be67e5fff6a7c02d638b68ada0097bac/docs/MIRROR_CONTRACT.md#L20).
- Chronic-disease response narrative preserves specific acute exacerbation, medication/access support, preventive intensification and stable monitoring branches. Source outputs are compact bits composed by PE; input analysts project external observations only when not machine-ready. They do not determine final RE workflow state. [narrative](https://github.com/jateeter/RealityEngine_Machines/blob/7d9bf071a8f1f28355712dd7633ed870302b3783/docs/HOME_CHRONIC_DISEASE_RESPONSE_INTERCONNECT_NARRATIVE.md#L1), [projection](https://github.com/jateeter/RealityEngine_Machines/blob/7d9bf071a8f1f28355712dd7633ed870302b3783/docs/HOME_CHRONIC_DISEASE_RESPONSE_INTERCONNECT_NARRATIVE.md#L55).

### Inferences

- Safety recognition and approved urgent routing must remain deterministic/nonblocking; RAG may explain or draft follow-up, but must not delay recognition waiting for model availability.
- Production onboarding must turn the dev-open mechanisms into explicit scoped authorization; the package cannot claim booleans or named reviewers authenticate a person.

### Gaps

- No live devices, PIM/POD, PE endpoints or model calls were exercised. Source code search found published-bus metadata/narratives but no `published-domain-bus`/`peCompositionRequired` handling in reviewed C++, LSP or Scala source. Actual source-to-bus composition implementation/trace requires verification, not assumption.

## Are generated AI agents, action execution and RAG complete?

### Takeaway
There are 43 materialized input analysts and existing default personal-health RAG machinery, but named completion contracts disagree and the inspected terminal output dispatcher remains a recorder. Source seeding and model tools should be preserved and strengthened with reviewed sources, scoped evidence receipts and a verified action worker.

### Cited Findings

- All 43 generated health-personal specs are input analysts; source machines separately carry one explicit output `agentBinding` (HomeTransportationBarrierMonitor). Other workflows have trigger/governance metadata and sidecar-generated actions. Agent role existence does not establish tool/action implementation. [agent index](https://github.com/jateeter/localOpenClawStack/blob/f679704ffc6d98d80e34ccdaf8631b01ac74ec27/machine-behaviors/agents/index.json#L10149), [example input spec](https://github.com/jateeter/localOpenClawStack/blob/f679704ffc6d98d80e34ccdaf8631b01ac74ec27/machine-behaviors/agents/health-personal/home-social-isolation-monitor.oc-agent.json#L1).
- Exhaustive read-only JSON comparison: 2/43 `openclaw.completionSourceMappingId` IDs resolve in checked CI config (FacilitiesMaintenance and HydrationMonitor); 28/43 `agentBinding.writeBack.sourceMapping.id` resolve. Of 28 mapped bindings, four pointer lists exactly match generated input-axis keys, 24 differ (some hyphen/underscore, others entirely different axis vocabulary). These counts are current static config comparisons, not proof every completion fails: direct region/value routes exist. Bridge-fed inputs must not be blindly overridden by new generated assessment sources. [registration identity and pointers](https://github.com/jateeter/localOpenClawStack/blob/f679704ffc6d98d80e34ccdaf8631b01ac74ec27/machine-behaviors/register_input_mappings.py#L48), [bridge-fed caution](https://github.com/jateeter/localOpenClawStack/blob/f679704ffc6d98d80e34ccdaf8631b01ac74ec27/machine-behaviors/register_input_mappings.py#L102), [CI mappings](https://github.com/jateeter/RealityEngine_CI/blob/54e4666c775e9497f0dd666044e3daa1b10b91f9/config/integrations.example.json#L537).
- Exhaustive generated-axis inventory: 403 axes,355 wholly blank low/mid/high anchors. The example maps risk bits as scalar0–1 and uses a direction-agnostic phrase fallback `crisis=.05`, `absent=1`; preserve native binary, nominal ordinal and continuous meanings rather than asserting one universal score interpretation. [example axes/fallback](https://github.com/jateeter/localOpenClawStack/blob/f679704ffc6d98d80e34ccdaf8631b01ac74ec27/machine-behaviors/agents/health-personal/home-social-isolation-monitor.oc-agent.json#L40).
- C++ terminal dispatcher builds DispatchRecord `status=recorded`, attempts0, stores in memory, broadcasts creation. The inspected function contains no provider invocation; a separate consumer must be established. [dispatch_triggers](https://github.com/jateeter/RealityEngine_CPP/blob/1a668235bc84b53a88f6adb162c53538041ea7df/src/perception_engine_server.cpp#L3922).
- localAI GraphQL `updateProcessState` logs to a128-event in-memory deque and returns process state. This mutation is not an action agent worker or durable outcome store. [event buffer](https://github.com/jateeter/localAIStack/blob/4546f7a8daa0589e043075a6fc6efea05ffcc20b/services/api/routers/graphql_endpoint.py#L80), [mutation](https://github.com/jateeter/localAIStack/blob/4546f7a8daa0589e043075a6fc6efea05ffcc20b/services/api/routers/graphql_endpoint.py#L110).
- Unlike LifeBalance's new procedural package, existing Personal Health RAG is implemented: nine tracked Markdown documents (`wellness_baselines`, `health_state_interventions`, `sleep_quality`, `stress_and_hrv`, `recovery_protocols`, `hrv_interpretation`, `heart_rate_guide`, `nutrition_and_recovery`, `wearable_metrics`). `seed_default_corpus` reconciles them into both generic and health logical collections. [health_docs](https://github.com/jateeter/localAIStack/blob/4546f7a8daa0589e043075a6fc6efea05ffcc20b/services/api/core/health_docs.py#L1), [seed implementation](https://github.com/jateeter/localAIStack/blob/4546f7a8daa0589e043075a6fc6efea05ffcc20b/services/api/core/rag_seed.py#L176).
- Agent `health_search` calls the health vector store, retrieves8, health-reranks and returns4 excerpts labeled by category. Generic `rag_search` supplies filenames. This is executable tool plumbing, but not permission-aware immutable passage receipts. [agent tools](https://github.com/jateeter/localAIStack/blob/4546f7a8daa0589e043075a6fc6efea05ffcc20b/services/api/graphs/agent_graph.py#L33).
- Public RAG query takes only `question` and returns answer/sources/rewrite_count. Retrieve-only API similarly lacks domain/subject filters and exact source hash/span receipt, and emits engine signals. Document loader metadata is source/category/seed, not the desired source review/effective/scope evidence contract. [RAG route](https://github.com/jateeter/localAIStack/blob/4546f7a8daa0589e043075a6fc6efea05ffcc20b/services/api/routers/rag.py#L24), [retrieval effects](https://github.com/jateeter/localAIStack/blob/4546f7a8daa0589e043075a6fc6efea05ffcc20b/services/api/routers/rag.py#L107), [document metadata](https://github.com/jateeter/localAIStack/blob/4546f7a8daa0589e043075a6fc6efea05ffcc20b/services/api/core/health_docs.py#L62).
- Existing nutrition reference contains numerical protein, supplements and hydration guidance but its frontmatter is category/source only. Do not automatically adopt it as a qualified reviewed clinical source pack or copy its numerical recommendations into desired workflows. A source-review and provenance backlog is required. [existing nutrition document](https://github.com/jateeter/localAIStack/blob/4546f7a8daa0589e043075a6fc6efea05ffcc20b/data/health/documents/nutrition_and_recovery.md#L1).

### Inferences

- Preserve real RAG tools and reconciliation while adding role separation, qualified source review, consent/tenant filters, exact passage receipts, revocation, contradiction and injection tests.
- Action dispatch, notification delivery, patient acknowledgement, care-team acceptance and actual outcome are separate statuses; RAG cannot fabricate any of them.

### Gaps

- No health-personal output-agent implementation was established in examined service Python files by agent-family name searches. This is bounded code-inspection evidence, not a claim that no deployed separate consumer exists.

## What was checked and what acceptance remains?

### Takeaway
Existing contract tests protect some semantics, but end-to-end action execution and current-source provider/RAG acceptance remain unproven in this review.

### Cited Findings

- Executed read-only at current Machines checkout with `PYTHONDONTWRITEBYTECODE=1`: `python3 -m unittest discover -s tests/contracts -p '*bus_test.py'` -> 4 tests OK; `python3 -m unittest discover -s tests/contracts -p 'agent_contracts_test.py'` ->10 tests OK. The bus glob currently captures only matching filenames; this is not the entire semantic-bus suite. [patient bus contracts](https://github.com/jateeter/RealityEngine_Machines/blob/7d9bf071a8f1f28355712dd7633ed870302b3783/tests/contracts/patient_safety_transport_bus_test.py#L1), [agent contracts](https://github.com/jateeter/RealityEngine_Machines/blob/7d9bf071a8f1f28355712dd7633ed870302b3783/tests/contracts/agent_contracts_test.py#L1).
- HealthKit ingest parity test and health pipeline e2e tests already exist; they were inspected but not executed against a live universe. [HealthKit spec](https://github.com/jateeter/RealityEngine_Machines/blob/7d9bf071a8f1f28355712dd7633ed870302b3783/tests/integration/healthkit-ingest-contract.spec.ts#L1), [health pipeline](https://github.com/jateeter/localAIStack/blob/4546f7a8daa0589e043075a6fc6efea05ffcc20b/services/api/tests/e2e/test_health_pipeline.py#L276).
- OWL tests explicitly require a checked-in ABox for every health-personal machine and declared action vocabulary; preserve this semantic projection rather than replacing outputs with generic wellbeing labels. [OWL tests](https://github.com/jateeter/RealityEngine_Machines/blob/7d9bf071a8f1f28355712dd7633ed870302b3783/tests/contracts/owl_semantics_test.py#L94).

### Inferences

Required acceptance: authentic device or synthetic input with raw provenance; correct codec/units; scope remove vs lock; TTL and no-data behavior; native recognition and PE bus branch; prompt-independent urgent routing; verified provider dispatch; authorized action and acknowledgement; completion/writeback and later outcome; duplicate/stale/restart cases; reviewed RAG citations, permissions and unavailable-source abstention. Nutrition examples require patient-approved restrictions/plan targets, not generic healthy-adult targets.
