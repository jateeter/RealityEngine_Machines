# Acceptance design

The [case matrix](cases.json) defines named obligations, expected behavior and evidence. `NOT_RUN` is not a pass. Offline package verification only checks files/contracts and local negative policy fixtures. Existing read-only checks run during the audit are recorded separately in `verification-summary.json`.

Before release, RealityEngine_CI must pin current source/build/model/index/config provenance and exercise the complete synthetic daily loop against supported engines, source adapters, authorized evidence, a real provider, permitted test tools and acknowledged response. Report unavailable/not-configured/unsupported/failed/passed separately. No fake sensor, reviewer or provider receipt can close an integration gate.

Source-first work: reconcile completion IDs/axes, native projection anchors, provider/composer ownership and shared-lane conflicts. Evidence work: review existing seed sources, add scoped passage receipts, auth/revocation and source freshness. Operations work: implement durable action workers, valid contacts/runbooks, exact-revision review and idempotent recovery. Broaden only after one complete trace, then test all ten documentary groups and all18 declared buses. Clinical validation is a separate gate.
