# Acceptance design and release evidence

This file describes required tests, not executed acceptance. Live implementation remains tracked in Machines #225.

- A: Package integrity — hashes, internal references, 110 machine duties, ten family cards and acyclic document dependency graph. Run the included verifier.
- B: Grounded nutrition loop — synthetic subject, approved exact passages, real provider turn, validated proposal, exact-revision authorization, allowed test tool, completion, evening review and next-day feedback. Evidence-unavailable must not generate unsupported personalized recommendations.
- C: RAG isolation — no cross-subject/tenant disclosure; review/fixture text cannot become clinical authority; revoked content removed; stale/contradictory evidence handled; prompt injection cannot grant tools. Benchmark targets must be approved before release.
- D: Quantitative tracking — test units, raw/prepared amounts, unknown portions/nutrients, recipe double counting, corrected revisions and source lineage. Unknown does not count as zero intake.
- E: Action safety/recovery — denied/expired approval, wrong revision, malformed model output, wrong region, duplicate callback, timeout, restart and cancellation yield correct state and no duplicate effect.
- F: Whole domain — repeat positive, negative, missing-data and correction cases for all ten families; exercise cross-family conflicts and the four composed LBL096–099 journeys plus LBL100 feedback.
- G: Live integration — RealityEngine_CI records current source/build/model/config/index provenance and provider receipts; test supported engines with explicit participation. Report unavailable/not-configured/unsupported/failed/passed separately. Vector parity is distinct from action completion and clinical benefit.

## Evidence record per scenario

Store case ID, expected behavior, authentic inputs, current source revisions, index/model versions, steps, observations, approval/tool receipts, actual result, pass/fail basis and limitations in a private authorized test store as appropriate. Never fabricate a passing receipt. Commit only synthetic fixtures and non-sensitive summaries.
